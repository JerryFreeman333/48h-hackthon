> 状态：**草案**，等维护人 review。  
> 取代：v3 §8.3 的 4 行骨架为可实施 spec。  
> 适用模块：`modules/c-report/`（**全程不碰根工程 / A / B / packages**）。  
> 不依赖：根目录挂载（§8.2 单独评审）、公共 ModelClient（仍用 C 私有 ModelPort + fake）。  
> 与 v3 既有契约的关系：保持公共 1.0.0 strict、C-08 unknown 不画绿、C-11 模型职权最小化、C-12 不可变版本、C-17 cost null≠0、P2 所有权=项目访问控制+P3 同快照。

## 1. 一句话范围

把 C 的"创建 → 执行 → 完成"短路径扩成"**创建 → 阶段执行 → 落盘 / 重试 → 完成 / 取消 / 失败**"四态长路径：
- **取消**：可由调用方或运行时强制中断；阶段边界处检查，立即落 `cancelled`。
- **重启 / 断点续跑**：阶段结果原子落盘；新进程启动可识别"未完成 run"并从下一阶段恢复。
- **外部失败恢复**：可重试错误（超时 / 5xx / 网络）按预算退避；预算耗尽才升级为 `failed`。

## 3. P5 设计原则（与 v3 §10 既有原则对齐）

1. **确定性优先**：checkpoint 记录**已完成的阶段产出**，未完成的阶段下一轮重跑（不存中间结果）。模型精炼除外——已接受维度要原子重放，不重跑。
2. **不变性不被破坏**：checkpoint 写入不修改输入 `MatchReport` / `StoredReportVersion` / `ReportIndexRecord`；同 checkpoint hash 必出同输出。
3. **C-12 / C-08 / C-11 / C-17 全继承**：checkpoint 含 `promptVersion`；cancelled run 不被删除（canceled run 同样保留在索引里以便复盘）；retry 不增加成本已知上界。
4. **fake runtime 优先**：P5 全程在 `adapters/memory/` 内测试；不引入生产数据库 / 队列 / 调度器接口。
5. **公共契约 1.0.0 不动**：不新增 `report.*` 公共键；cancel/checkpoint 属于 **C 私有诊断与私有存储**。
6. **预算先于调用**：与 P4 模型预算同构——`RetryBudget` 在每次外部调用前 reserve。

## 4. 接口 / 类型提案（C 私有，不进公共 schema）

### 4.1 RunStore 扩展

```ts
// application/ports.ts（追加，不删不改）
export interface CRunStore {
  // ... 现有 5 个方法不变 ...

  /** 检查 run 是否已被标记取消（与 status=cancelled 等价但无 IO 查表）。 */
  isCancelled(projectId: string, runId: string): Promise<boolean>;

  /** 订阅取消事件（cooperative 取消的关键）。同一 runId 多次订阅互不覆盖。 */
  addCancelListener(projectId: string, runId: string, fn: () => void): () => void;

  /** 标记 cancel；语义等同 cancel(projectId, runId) 并保留完整 runStore。 */
  requestCancel(projectId: string, runId: string): Promise<{ wasRunning: boolean }>;
}
```

设计选择说明：
- **不引入"暂停/恢复"枚举**：v3 没要求；加暂停=扩大范围、超出 P5。
- **`requestCancel` 返回 `wasRunning`**：handler 据此决定返回 202（已排队/正在跑）或 409（已完成/已失败/已取消，幂等友好）。
- **listener 不绑定一次性**：取消被消费后 listener 自动失效（同 AbortController），避免泄漏。

### 4.2 CheckpointStore（新增端口）

```ts
// application/ports.ts（新增）
export interface CheckpointStage {
  stage: string;                    // 'preferences' | 'constraints' | 'dimensions' | 'questions' | 'reasons' | 'action' | 'report_selfcheck'
  completedAt: string;              // ISO
  partialOutputHash: string;        // SHA-1 of stage output JSON（仅用于完整性校验，不用于决策）
}

export interface RunCheckpoint {
  runId: string;
  projectId: string;
  reportId: string;
  version: number;
  ruleVersion: string;
  promptVersion: string;
  inputHashes: { profile: string; intent: string; bundle: string };
  completedStages: CheckpointStage[];
  /** 已完成阶段的最小重放集合：每个 entry 是该阶段运行所需的固定输入与产出（保留到下一阶段）。 */
  stageOutputs: Record<string, unknown>;
  modelUsage: ModelUsageEntry[];    // 见 P4；与 model refine 复用
  startedAt: string;
  lastCheckpointAt: string;
}

export interface CheckpointStore {
  /** 原子：以 completedStages 增量推进；不删除已完成阶段。 */
  appendStage(projectId: string, runId: string, stage: string, stageOutput: unknown): Promise<void>;
  read(projectId: string, runId: string): Promise<RunCheckpoint | null>;
  /** 标记结束（completed / cancelled / failed），保留 checkpoint 仅供诊断。 */
  finalize(projectId: string, runId: string, finalStatus: 'completed' | 'partial' | 'cancelled' | 'failed'): Promise<void>;
  /** 列出 project 下未 final 化的 run，用于启动时恢复。 */
  listInterrupted(projectId: string): Promise<RunCheckpoint[]>;
}
```

**重要约束**：
- `stageOutputs` 仅保留**确定性管线**的产出（perJob eval、validatedBundle、validatedProfile、validatedIntent、hardPrefs、factIndex、perJob、traces）。**模型精炼的中间维度摘要（accepted summary）也保留**，但已接受维度若被拒绝要在 `modelUsage` 里有对应条目。
- 不存 `MatchReport`：报告只在最终阶段 `report_selfcheck` 通过后由 handler 落 `reportVersions` / `reportSnapshots`（不可变）。checkpoint 只用于恢复。
- 不存决策缓存：恢复后 `report_selfcheck` 必跑 schema 自检。

### 4.3 RetryPolicy（新增端口）

```ts
// application/ports.ts（新增）
export type RetryableUpstreamError =
  | { kind: 'timeout'; afterMs: number }
  | { kind: 'http_5xx'; status: number }
  | { kind: 'network_reset' };

export class NonRetryableUpstreamError extends Error {
  constructor(public readonly status: number | null, message: string) { super(message); }
}

export interface RetryDecision {
  attempt: number;                  // 1-indexed
  nextDelayMs: number;              // 0 = 不再重试
  reason: 'retry_budget_left' | 'non_retryable' | 'budget_exhausted';
}

export interface RetryPolicy {
  /** shouldRetry 由实现判定；预算耗尽 / 不可重试 → reason 非 retry_budget_left。 */
  shouldRetry(error: unknown, attempt: number): RetryDecision;
}

export interface RetryBudget {
  reserve(): void;                  // 调用前 reserve；预算耗尽抛 RetryBudgetError
  get callsUsed(): number;
}
```

**判定规则**（写死在 `DefaultRetryPolicy` 实现里，handler 用 ctx 注入）：
- `RetryableUpstreamError` → 退避 `2^attempt * 100ms + jitter[0,100ms]`，默认 max 3 次
- `NonRetryableUpstreamError`（4xx / 解析错误）→ `reason: 'non_retryable'`，不重试
- `Error` 其他 → `reason: 'non_retryable'`，不重试（不冒"什么都重试"的风险）

**与 P4 的关系**：`refineReportWithModel` 当前的 §13 "响应丢失不盲重发"语义被 **加严** 为"响应丢失**且**预算允许**→ 受控重试一次"；仍不允许多次盲重试。

## 5. 行为语义（按调用路径）

### 5.1 创建 run

```text
POST /api/c/matches
  → executeOrReuse:
    enqueueWithReservation (queued)
    updateStatus(queued → running, stage='input_schema')
    调 runMatchPipelineCancellable(input, ctx)   ← P5 新增；旧 ctx 没传则走同步 runMatchPipeline（行为不变）
      每个 stage 结束后：
          appendStage(stage, output)             ← ctx.checkpoint 注入时
          runStore.isCancelled(p, r) ? throw    ← C× listener 也触发
    pipeline.ok:
        updateStatus(running → completed/partial, 'report_selfcheck')
        insert reportVersions / reportSnapshots  ← 不可变
        checkpoint.finalize(completed/partial)
    pipeline.err:
        if PipelineCancelledError:
            updateStatus(running → cancelled, 'cancelled')
            checkpoint.finalize(cancelled)
            return 202 { status: 'cancelled' }
        else:
            updateStatus(running → failed, `failed:${code}`)
            checkpoint.finalize(failed)
            return domainError  (维持现有错误返回)
```

### 5.2 取消 run（新 API）

```text
DELETE /api/c/runs/:runId
  → handleCancelRun:
    authenticate (401)
    locateRun by id + project  → 404 跨用户读不泄露
    requestCancel(p, r):
      if run.status ∈ {queued, running}:
          标记 cancel flag + 触发 listeners
          return { wasRunning: true }
      else:
          return { wasRunning: false }    ← 已完成 / 已失败 / 已取消；幂等
    return 202 { runId, status: 'cancelled' | 'queued' | 'running' | 'completed' | ... }
    if wasRunning=false && 旧状态非 cancelled:
        return 409 RUN_NOT_CANCELLABLE
```

幂等性：第二次 DELETE 同 runId → `wasRunning=false` → 409 with `currentStatus`。

### 5.3 重启 / 断点续跑

```text
on DemoRuntime boot (C api handler init):
  for each project in readableProjectIds(userId):
    checkpoints = ctx.checkpoint.listInterrupted(projectId)
    for c in checkpoints:
      if c.lastCheckpointAt < (now - 24h):           ← 超龄清理，不在本 run 范围
          skip (留作后期 GC，本期不实现）
      else:
          resume(c):
            run = await ctx.stores.runs.read(projectId, c.runId)
            if run.status === 'running':             ← 真实在跑（双进程？），跳过
                skip
            nextStage = nextStageAfter(c.completedStages)
            await ctx.stores.runs.updateStatus(...,'running', nextStage)
            从 nextStage 起重放 runMatchPipelineCancellable：
                前置：把已完成的 stageOutputs 直接喂入对应函数（不重跑）
                后续：从 nextStage 开始正常 appendStage + 阶段检查
```

恢复路径必须**幂等**：已完成的 stage 跳过（不 appendStage），未完成的 stage 重新 appendStage（覆盖之前的 partial）；恢复后 `lastCheckpointAt > checkpoint.lastCheckpointAt`，且 `reportSelf.stage = 'report_selfcheck'` 仍要 schema self-check。

### 5.4 外部失败恢复

模型精炼的每个 `complete()` 调用前：

```text
try:
    retry_policy.shouldRetry(prevError, attempt) → { nextDelayMs, reason }
    if nextDelayMs == 0:
        raise ModelRetriableExhausted(prevError)
    await sleep(nextDelayMs)
    retry_policy.budget.reserve()
    return await port.complete(req)
catch NonRetryableUpstreamError as e:
    raise  (按现有 transport_error 路径降级)
catch ModelBudgetError:
    raise  (预算门已耗尽)
```

**关键不变量**：模型最多被调 `maxAttempts` 次（默认 3），其中至少 1 次必须 `complete()` 返回非 transport_error 才允许 refine；失败则**该岗位**回退模板（行为与当前 P4 一致）。

## 8. 不会做的事（明确非目标）

- **暂停 / 恢复**（v3 没要）
- **多进程并发协调**（仅单 fake runtime；生产侧需 DurableScheduler，本期不接）
- **run 自动租约 / 超时杀**（v3 §8.3 没要；handler 已在 cancel/检查点上铺好，未来加 `maxRunningMs` 不破坏既有契约）
- **checkpoint GC**（超龄清理留作后续；本期只 finalize，不删）
- **跨模块取消传播**（A/B 各自的 run 不知道 C 在跑；C 只管 C 自己的）
- **公共 ModelClient adapter**（属于 §9 待办第 3 项）
- **任何根目录挂载**（属于 §8.2，独立授权）
