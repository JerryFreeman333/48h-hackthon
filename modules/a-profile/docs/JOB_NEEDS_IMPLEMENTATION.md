# A七主题求职需求流 · v0.7

## 定位与流程

A记录本人求职需求与现实条件，不评估能力，不调查公司，不生成最终岗位匹配结论。本轮根据用户指令替换当前活动问题，而不是把新题套到旧兴趣／人格量表。

七主题21个选择问题 → 现实条件、求职阶段与目标、行业与岗位类型 → 可读侧写 → 本人确认 → 冻结版本 → 完整JSON／Markdown。可以缺答或暂不确定；所有用户填写项均为选择，文件入口只接受本模块导出的规范JSON，不接受简历、图片或能力资料。

主题是晋升成长、薪酬透明、工时休息、五险一金、团队文化、企业经营稳定、职位与用工稳定。每个主题记录关注程度、具体核验项目、未知处理方式，不计算心理维度分或风险分。

## 代码与真实后端

- `src/needs/catalog.mjs`：中文问题、稳定ID、选择项及主题研究来源。
- `src/needs/service.mjs`：Zod严格校验、会话归属、乐观并发版本、确定性语义编码、确认、不可变版本、导入导出及报告。同一答案生成同一侧写信息；没有模型调用。
- `src/needs/archive.mjs`：启用新流前对旧state按完整字节备份，SHA-256核验；存档失败不继续启动。
- `src/server.mjs`：活动`/api/a/needs/*`、HttpOnly同源Cookie、请求大小限制及错误响应。旧v2写入／计分／删除返回410，保留归属检查后的历史GET。
- `src/ui/needs.html`、`needs-app.mjs`：使用现有样式，纯中文选择、自动保存、前后页、恢复、本人确认、版本选择、完整JSON导入与导出。

状态实际写入本机`.data/state.json`，新流在独立`needs`命名空间中。保存先原子写入文件，再更新内存；版本修改不覆盖已确认快照。Cookie只能识别本机浏览器会话，不等于正式账户系统；当前服务器只监听127.0.0.1，不宣称已部署多人生产服务或数据库。

JSON checksum用于发现文件不一致，不是电子签名，不证明外部用户真实作答。导入逐项重建并核对答案、画像、意向、题目来源和报告的一致性，再生成新的归属ID；不接受自行添入的能力、分数或企业事实。服务端也拒绝选择列表之外的内容。

## 原算法与存档

四个文件保持Git blob完全一致：`battery.mjs`、`scoring.mjs`、`onet-mini-ip.json`、`mini-ipip.json`。原始正反向规则及计分回归测试继续运行，但活动新流不调用其评分或兴趣职业排序。新流的UserProfile使用既有`not-administered`、版本`1`，六个兴趣分全部null。

旧UI、旧入口浏览器测试、中间中文审阅资料和旧样例在 `rubbish/interest-personality-v0.6-20261002/`；更早48题在 `rubbish/legacy-20261002/`。旧服务实现仅用于历史读取及原算法回归。实际个人数据及私有译稿不会提交Git；原state备份在 `rubbish/private/needs-transition-<sha256>.json`。不将旧答案迁移成新需求，不将旧分数重新解释。

## 公共交接兼容

未修改公共ABC契约、B/C代码或公共基础能力。完整文件包含：

1. `UserProfile`、`SearchIntent`：继续遵守1.0.0，传递既有城市、最低固定月薪、销售KPI、出差、外包五类条件；能力字段保留空占位，表示未采集，不表示能力低。
2. `JobNeedsSnapshot`：A独立附表`a-job-needs-1`，保留七主题、原始答案、用户确认、来源ID及所需核验项目。关联同一个projectId、profileId和profileRevision。
3. `questionProvenance`、`Report`及checksum：来源与可读说明和答案一致，不再次生成不同算法结果。

**七主题尚未接入B/C判断。** 附表`handoff.status=requires-bc-needs-mapping`明确记录缺口；界面、JSON和报告都有说明。完整导出不提供会静默删除七主题的“降级”选项，新流也拒绝缺少附表的旧JSON导入。根项目的集成页面如果只读取UserProfile/SearchIntent，会仅看到旧契约条件，不能宣称七主题联调完成。

后续需由三方协调附表输入和证据映射，先明确岗位/团队/企业范围、来源日期、未知与冲突状态，再由C解释用户影响。`verify_first`在A只表示用户对信息缺失的处理意愿，不直接作为C动作；“重要”不自动转成硬约束。调查主题对应关系见下表，**这些是协调建议，不是新增公共Fact key**。

| A主题 | B应核验的信息范围 | C未来可解释的影响 |
| --- | --- | --- |
| 晋升成长 | 岗位/团队晋升规则、带教、发展路径与来源 | 是否回应本人关注，哪些仍未知 |
| 薪酬透明 | 岗位固定/浮动、计算及发放口径 | 口径不明对收入决策的影响 |
| 工时休息 | 岗位/团队工时、休息、加班安排 | 与本人工作边界的关系 |
| 五险一金 | 用工主体、适用法域、个人缴纳规则 | 适用保障与未知核验；不允许放弃法定义务 |
| 文化方式 | 具体团队沟通、评价与管理材料 | 具体工作方式偏好；不泛化整家公司 |
| 企业经营稳定 | 同主体经营、公开财务、重组等证据 | 持续经营信息对用户的意义，不能预测倒闭概率 |
| 职位用工稳定 | 招聘原因、合同、岗位及团队变化 | 该职位的持续性未知，不能预测裁员概率 |
