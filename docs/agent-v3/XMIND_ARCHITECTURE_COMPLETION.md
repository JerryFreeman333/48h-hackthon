## 这张图属于哪里

原图主要是 **B 调查 + C 判断/解释 + 两者共用的证据与归档流程**。A 提供用户确认的需求，B 把需求变成具体问题、取得材料、记录主体和陈述；C 判断这些材料回答了什么、仍缺什么，生成解释和报告；C 的缺口再回到 B 做有界补查。首次公司建档没有 A 时，只调查公司背景，不生成用户满足结论。

队友截图中的多平台查询台体现“采集、建库、按板块展示”的路径。截图无法证明其内部问题契约、独立来源判断或个人需求解释已经实现，不能据此判定哪方更完整。本项目当前有只读候选库查询、公共正文与受控材料处理，专用平台爬虫按用户安排另补。因此两者有重叠，但不是仅把查询台复制为 C。

原文件：[一家公司完整Agent运行树.xmind](source/一家公司完整Agent运行树.xmind)。保存的设计索引为 `modules/research-agent/xmind/tree.json`，包含 **441 个节点、306 个叶节点、13 条关系线**，原文件 SHA256 为 `8d13171c008f3b6331dfcd3b826857bd361662b4fdc776d6b78838c5bc6efb49`。索引保留节点 ID、父子关系、标题和路径；登记全部节点不表示每个叶节点已实现或逐项用真实数据验收。能力接口明确返回 `allCapabilitiesImplemented:false` 和每项边界，不计算虚假的“100%完成率”。

## 实际运行方式

当前运行的是 **11 个专职 Agent 的持久任务图**：规划、路由、采集、主体、来源、抽取、传播信号、复核、解释、追问、归档。它们有各自的输入输出校验、依赖、工具白名单、任务状态和消息；追问会向规划 Agent 发消息并增加下一轮任务。失败的工序保留原因，其他可执行工序继续，已经取得的材料供后续 Agent 共用。

这不是 11 个独立大模型进程。明确规则由本机处理器运行；语义抽取、比较和解释共用 **默认关闭、每次调查最多一次** 的模型批次。每份报告分别记录 `rules` 或 `model`、调用次数、候选接纳/拒绝原因，不能把任务图名称当成模型已运行的证据。`xmind-execution/1` 保持兼容原来的十个报告角色；新增采集工序的真实任务、工具和依赖记录在 `xmind-collaboration/1` 中。

运行时由本项目实现，没有搬入 LangGraph、CrewAI 或 AutoGen。`runtime.ts` 的任务、消息和工具回执通过 Zod 校验后写入本机检查点；同一逻辑操作的结果可复用。恢复只读取原回执；已预留但结果不明的外部/模型调用不会自动再付一次费用。检查点有进程锁和配置指纹，不能把其他调查的回执拿来复用。

## 本地文件与 OCR

实际可导入文字、文本 PDF、DOCX、XLSX、CSV、PNG/JPEG 和扫描 PDF。原件经公共上传入口保存在当前实例本机目录，Office 解析和 OCR 不调用云服务。DOCX 提供主文档段落/表格定位；XLSX/CSV 提供表、行、单元格定位；扫描 PDF 提供物理页与文字框。OCR 来源全部要求复核，不能把识别字符串当真实雇佣承诺。

采用固定依赖 `python-docx 1.2.0`（MIT）、`openpyxl 3.1.5`（MIT）、`rapidocr-onnxruntime 1.4.4`（Apache-2.0）和 `onnxruntime 1.31.0`（MIT）。RapidOCR 固定版本 README 记录 PaddleOCR 模型来源，PaddleOCR release/2.7 项目许可为 Apache-2.0；实际本地 ONNX 文件哈希另行记录，不声称转换文件与上游权重字节相同。完整依赖许可、17 个直接/间接依赖和三份实际模型哈希见 [本地文档采用记录](../../modules/research-agent/v3/licenses/README.md) 与 `dependency-manifest.json`。这些依赖并非全部 MIT/Apache，安装包的 BSD、MPL-2.0 AND MIT 和 OpenCV 第三方声明均保留。

上限：主动导入 18 MB；OOXML 解压大小、条目和膨胀率受控；工作表最多 24、单表 5000 行/128 列、总 25000 单元格；OCR 最多 12 页、1600 万像素，默认 25 秒、硬上限 35 秒且服从剩余问题时间。运行时不下载模型。DOCX 不重建 Word 排版页码/页眉页脚/批注/嵌入图片；XLSX 公式只保存、不计算、不读外链；没有旧二进制 DOC/XLS、PPT、手写准确率或 OCR 表格网格重建承诺。没有接入 Docling 整套框架。

## 语义路径与隐私边界

`runXmindSemanticBatch` 会从**已经取得并接纳、带可定位正文的公共 HTTP 或文本 PDF**选择有限材料，生成结构化抽取/比较/中性解释候选。保留原 V3 的 8 条正文、每条最多 1600 字符、一次调用与最多 2048 输出 token 上限；有更小配置时取更小值，问题最多 48 个，并服从当前时间预算。截断不保留分号后条件未完的句子。默认不开启；配置存在只表示 `configured_unverified`，不能宣称实际服务效果通过。

程序逐项检查完整原句、正文位置、公司法定全名、岗位/团队范围、字段原文支持、否定对象、条件、时期和工资口径。错误主体、坏引用、缺失条件、年度总包换算固定月薪、凭空币种和范围不符的解释保留拒绝原因。接纳后仍只是来源陈述，再交规则评估；语义比较与解释不能自行升级满足状态。仅解释而没有新陈述时也保留其证据 ID 与完整原句。

用户文件/群聊、个人偏好、阈值、问卷原句和 JD 私稿不进入这个批次；待复核 OCR 材料也被排除。外部正文中的指令只是数据，模型没有工具权限；要求调用工具、坏结构或请求失败时保留规则结果与未知。调用前把预算预留和 `reserved` 语义记录持久化，成功/失败后保存原结果；已知付费预留但无确认回执时不重复调用。本轮没有发起真实模型调用，线上模型/中文全语义效果仍是外部未验收项。

## 时效与复核积压

`sourceFreshness(snapshot,bundle,now?)` 区分有效窗口内、已截止、尚未生效、日期不明确、历史期间、有日期参考、无日期和不可用。`targetedRefreshQuestions` 只列受影响的当前问题、原因及可接受材料；历史报告和历史事实原文保持。访问失败不被算成“内容过期”或企业风险。

`normalizeReviewQueue` 按陈述原文/命题指纹与问题范围合并，避免换了陈述 ID 就重复排队。原人工决定或 deferred 在证据和规则未变时保留；来源变化或规则版本变化才重开，并留先前决定。没有维护者的任务自动 deferred，含需要检查的引文、主体、条件、否定对象与未完成原因；不让内部积压强迫用户逐条维护，不把机器 auto_checked 改名成人工已审。

## 验证范围与仍缺的工作

当前新增测试均被 `package.json` 的 `test`、`test:agent` 和 `test:v3` 的 `xmind/*.test.ts` 正式入口纳入。我们对本页新增部分实际完成了语义 13 项、时效/队列 8 项、能力/主体图 4 项的定向规则测试，最终合计 **25/25 通过**，最新 `npm run typecheck` 通过。受控模型响应覆盖成功、失败、坏引用/注入、否定/条件、工资口径、范围、仅解释引用、预留与结果持久化，以及原输入/输出预算不扩大。它们验证程序，不证明模型在线运行或中文全面效果。文档解析已使用明确标记的合成中文 DOCX/XLSX/GB18030 CSV/PNG/JPEG/扫描 PDF 实际运行；完整测试、HTTP/UI 与独立目录最终结果由 [本轮验收记录](XMIND_ARCHITECTURE_ACCEPTANCE.md) 分别列出，不用单项通过代替全套通过。

未完成项如下，能力接口也保留这些状态：

1. **逐平台自动爬虫/授权接口/动态登录**：按用户本轮先补架构、后补爬虫的安排延期。通用 HTTP、主动导入和来源路由已可运行，但不保证每个平台正文访问成功。
2. **真实模型服务验收与中文金标准**：有实际调用/校验/恢复接口，默认关闭；本轮未使用付费模型，不声称全语义抽取/隐含条件/中文冲突处理已验证。需既定凭据与既定预算下单独验收，不扩大费用。
3. **真实群聊与协同检测效果**：自动客户端/机器人未接，真实账号/时间/历史不齐；只保留受控元数据可解释信号，不判水军或真假。
4. **独立人工认证**：复核队列、状态保留和版本入口已实现，真实材料的独立人工认证未完成，报告依然区分陈述、回答、证实、满足。
5. **复杂文件与中文 OCR 总体准确率**：本机固定解析器已跑受控格式，复杂布局/页眉批注/表格网格/手写/旧二进制格式等未覆盖；OCR 始终需复核。
6. **原图每个叶节点的真实材料验收**：306 个叶节点尚未分别验收；工具名是候选方案，不能把“列出工具”或“替代基本能力”说成运行了整套开源项目。

下一步在最终验收通过后，按缺字段最多、公开访问可行且投入可控的来源补一个平台连接器，并比较真实同目标材料的覆盖与引用质量。开始接入前保持本轮可运行 A→B→C、只读库、默认开关和旧报告回退路径。
