# 用户视角黑箱测试：2026-10-03

## 结论

当前产品可用于受控联调演示，尚不适合直接作为成熟产品交给普通用户。核心规则及版本链路成立，但新建需求、跨页面草稿保存和错误恢复有明确问题。**结论置信：高（实际流程缺陷）；中（对用户体验与修复优先级的判断，未做真人用户研究）。**

## 缺陷与修复验收条件

### F01：A“暂不确定”模式无法开始（P1，高置信）

复现：打开 `/profile?new=1` → 模式选择“暂不确定” → 开始填写。页面留在开始页，显示“只接受当前选择与版本，输入字段或格式不正确”。干净页面独立重复过，排除了旧导入错误的影响。

用户影响：一个公开可选择的分支不可用。修复验收：该模式进入问卷并保持未知，或移除无业务含义的开始页模式；不能让用户选择一个必然报错的选项。代码原因未以黑箱确认，不在这里编造根因。

### F02：新需求刷新不能直接恢复（P1，高置信）

复现：由新需求入口开始 → 填选主题并前进 → 页头显示“已自动保存” → 返回主题1并刷新。`new=1`仍在URL，页面回到“开始填写”；再开始进入新记录，原答案没有直接出现。

用户影响：中途刷新后无法继续原问卷；不是仅丢当前滚动位置。精确sessionId入口另测可恢复，所以不能泛化成全部A数据持久化失效。后台是否仍保留此草稿没有通过黑箱确认。

修复验收：新建会话后进入包含其sessionId的可恢复地址，刷新同一主题/草稿可继续；开启真正的新记录仍应是用户的明确动作。

### F03：补充需求使JD草稿清空（P1，高置信）

复现：分析页填写“黑箱草稿保留测试”和一段JD → 点击补充七主题需求 → 点击用需求分析一份JD返回。岗位和JD文本均为空。

用户影响：用户遵循产品引导后需要重新找和粘贴资料。修复验收：跨页保存草稿；返回时保留岗位、正文、公司、地点及来源，并绑定刚确认的需求版本。至少要明确提示离开会丢草稿，不能无声清空。

### F04：错误提示暴露内部校验结构（P2，高置信）

实际输入包括空白岗位、空白JD、1000/501字符岗位名、javascript链接、带凭据HTTPS链接、仅日期 `2026-10-03`。数据均被拒绝，这是校验通过；但是界面直接显示 `path`、`origin`、`maximum`、英文message，日期错误还展示长正则表达式。

修复验收：字段旁给出中文、具体且可纠正的提示，如“岗位名称最多500字”“发布日期需包含时间和时区”；内部详情进入诊断日志。功能校验通过不等于用户反馈通过。

### F05：同义否定表达识别不稳定（P2，高置信）

同一原岗位、需求版本1、拒绝销售硬条件的对照：

| 新JD片段 | 下载中的事实 | 约束结果 |
|---|---|---|
| 无销售KPI，无陌生客户开发 | facts为空 | 销售无法判定 |
| 销售KPI：无。负责产品运营 | job.sales_kpi=false，supported | 销售通过，其他未知仍保留 |
| 销售KPI：无。无客户签单责任 | job.sales_kpi=false，supported | 销售通过，其他未知仍保留 |

另一次“黑箱虚构资料，修订：销售KPI：无…”也未形成相应事实，见material.json。正反并列“销售KPI：有。销售KPI：无”保留未知，没有强行选一边；这是正确的保守处理。

这是常见写法导致的信息漏读，不是已经证明会把否定误判为有销售，也不是在声明公司的现实考核被核实。修复验收：明确支持范围、用成组正反/否定/矛盾语句检验抽取；在资料摘要中展示“JD声明”和“独立核实”两个层级。

### F06：已支持false事实却说无已协调事实（P2，高置信）

negation-1.json里存在supported `job.sales_kpi=false`，硬条件表显示销售通过；同份报告职责清晰度说明却写“没有已协调的supported销售KPI事实”。

修复验收：区分true、false、缺失、矛盾；false时说“JD声明无销售KPI，其他职责和考核仍待核实”。保留职责维度未知没有问题，问题是证据描述失真。

### F07：成功后残留旧红色错误（P2，高置信）

复现：导入checksum改为tampered-blackbox的测试包 → 被拒绝 → 导入从实际ABC下载包提取的原样aExport → 稍后侧写恢复为演示版本1，但红字仍显示“JSON校验不一致”。同样，开始页选择暂不确定报错后改真实模式，已进入问卷仍残留旧错误。

修复验收：新操作开始及成功时清理旧错误，并明确区分处理中、失败和成功。有效包确实恢复成功，不能把截图里的旧错误误读成有效导入失败。

### F08：报告手机整页溢出（P2，高置信）

390×844视口，DOM测量报告根scrollWidth约465px。硬约束表格右边界约464.6px，表格宽约442px，字段名和事实编号撑开列。页面出现整页横向滚动。

修复验收：手机下卡片/可滚动表格容器，不让整页横向溢出；技术字段和长编号应折行或移入详情。城市优先级横向导航自身滚动与整页溢出是两件事，不混为一谈。

## 阻挡、未确认及覆盖边界

1. **B人工资料链路当前不可验收。** 3000独立B人工/live返回本地开关/公共鉴权提示。另启动仅监听127.0.0.1的3002生产实例并设本地开关仍拒绝写入，随后停止测试实例。原因可能还与生产运行策略有关，根因未知。未改变生产鉴权，也没有把B材料来源/范围禁用控件记为已执行。人工检索、主体候选选择、材料多范围校验和薪资倒置的服务端结果因此未验证。
2. **A两个下载按钮未确认。** 正常保存页及精确会话重试点击，没有收到下载事件；相同浏览器的报告、C和ABC下载能取得实际文件。不能凭这一点确定是A实现还是该浏览器对下载方式支持的问题。有效恢复另用ABC的完整aExport成功验证，不是伪造一个符合结构的包。
3. **完整报告的外会话直接读取未得出权限结论。** 打开昨晚另一会话报告时浏览器显示客户端阻挡，不能将浏览器错误冒充已观察到的HTTP404或完整隔离通过。不存在报告的编辑页显示“本会话无该报告”已验证，完整授权隔离另需接口或独立浏览器测试。
4. 本轮没有跨浏览器、断网/延迟注入、多人并发、持久服务重启、真实模型、极长JD的全部边界和真实公司判断准确性测试。之前的服务重启测试不冒充本轮执行；在这一轮未证实的项目置信为未知。
5. 开始页新建与导入功能产生了多个显式测试记录；没有清空.data、删除用户需求或报告。

## 产品层面的下一步

先修F01–F03并回归三条完整用户旅程，随后修F04–F08。修复版本仍应用同一组原始输入，不能换成“更容易成功”的演示文案来验收。

还有三项中置信的体验判断：
