## 1. 产品目标：翻译企业材料，而不是搜索七种结论

X-Ray 面向求职者。把企业的经营、招聘、公开披露和员工经历，翻译成“这份工作可能如何影响我，我应当进一步核实什么”。它不是投资分析网站，也不是以搜索命中数量衡量质量的舆情仪表盘。

用户提出的七个观察维度：

1. 精神空间：尊重、自主性、管理压力、表达空间等。
2. 薪资透明：固定薪资、浮动部分、发放条件、奖金口径、招聘承诺清晰度。
3. 劳动时长：工时、加班、双休、值班、出差、补偿安排。
4. 五险一金：缴纳承诺、基数、比例、资格、福利适用范围。
5. 企业文化：管理和协作方式、员工体验、制度与实际经历是否一致。
6. 企业稳定：经营趋势、现金和债务、重大经营风险及公开事件。
7. 职位稳定：岗位所在业务、合同主体、外包或派遣、项目周期、岗位变动线索。

注意：现有内部 `growth` 字段可能表达晋升空间，用户本轮表达的是“精神空间”。先核对现有页面、需求与契约，记录两者差异；不要把精神空间偷偷改成晋升空间，也不要直接把所有 growth 数据解释成精神空间。优先在内部扩展概念和报告映射，维持既有公共接口；必要的公共契约改动必须同时更新生产者、消费者、版本、迁移和测试。此次无需重做用户画像问卷。

正确主线：识别企业和岗位 → 按渠道搜集材料 → 共享证据库 → 按问题提取事实与比较 → 根据求职者关注点翻译 → 给出证据、限制和核实问题。

不要只搜“某公司福利好不好”“某公司稳定吗”。应搜索和读取能支持判断的原始材料：财报、审计意见、公告、招聘说明、公开信用事件、采购文件和有范围信息的员工经历。七个维度是解释层，不是七个互相隔离的搜索仓。

### 不可越过的推理边界

- 营收或利润下降，不直接证明裁员、拖欠工资或某岗位会被取消。
- 集团财报，不直接证明子公司、部门或岗位的待遇。
- 注册资本不是现金余额；资产总额不是可用于发工资的现金；收入、利润、经营现金流必须分开。
- 招聘广告的年薪不直接等于固定月薪。奖金条件和税前税后未知时保留未知。
- 员工帖子是带范围的经历或声称，不直接成为企业普遍事实。重复转载不等于多人独立印证。
- 采购公告是计划或采购动作，不证明福利已交付；中标、合同、验收是不同阶段。金额也不直接等于人均福利。
- 找不到公开报表是资料缺口，不能算企业稳定或不稳定。
- 正面/负面情绪与事实是否获得证据支持是两件事。情绪只能辅助描述。
- 同一材料可关联多个维度；保留原文，不能让每个 agent 只传递自己的总结。

## 4. 最小可用架构

```text
现有用户关注点 + 选中公司/岗位
                 |
          身份解析与任务计划
                 |
      有界调度器：四类渠道工作器
       /       /        \         \
 企业信用  企业披露  招聘与采购  社区经历
       \       \        /         /
       统一证据库 + 渠道执行状态
                 |
     事实提取、范围核对、同源去重
                 |
       矛盾审查与有预算的缺口补查
                 |
      求职者翻译与原有报告集成
```

按渠道分采集职责，按问题组织解释。四个工作器可以是确定性代码加少量模型决策，不要求四个独立模型进程；如果只有静态解析，就称适配器。多 agent 的价值在策略和证据协作，不在数量。

### 四类渠道职责

**企业信用工作器**：工商主体、法人/品牌关系、公开信用与处罚等记录。天眼查、启信宝、企查查应作为各自独立适配器候选；只使用本次授权边界内可访问的公开页面、搜索索引或已配置接口，不假设存在免费 API 或完整报表。官方公开来源也可支持此渠道。

**企业披露工作器**：官网、上市披露、年报、中报、审计报告、经营公告。针对公司上市地和代码发现文件、下载、解析内容。不得停留在“找到了年报标题”。私企没有公开报表时记录缺口。至少完成一个真实公开 PDF 的获取到引用闭环。

**招聘与采购工作器**：官方招聘、公开 JD、公开招投标及福利相关采购。区分采购主体、服务对象、时间与采购阶段；福利推断只作为有界线索。JD 关联岗位和城市，薪资结构保留条件。至少实现公开网页正文提取与采购信息字段提取，不能只写一个 provider 类。

**社区经历工作器**：小红书、知乎、微博、脉脉等公开可访问材料。每个平台独立适配器，允许使用搜索索引发现结果，但必须标为索引摘要。保留发帖时间、经历时间、部门岗位、员工身份是否未知和原始来源。无法取得正文/评论时明确说明，不能用模型补全。

### 采集技术边界

用户要求保持无需登录的公开侦查路线。本轮不引入账号登录、他人 Cookie、验证码绕过、隐藏接口逆向、代理轮换或访问限制绕过。允许公开搜索、公开且可访问的网页/文件、已经合法配置并在授权范围内的接口，以及用户主动提供的文件。遇到登录、验证或禁止访问响应，记录状态并走其他公开渠道。

无登录并不保证任意来源都允许无限采集。保持低并发、域名限速、超时、大小限制和清楚的来源清单；不得把搜索服务的限制包装成“直连平台成功”。不需要为每个普通公开请求询问用户。

为天眼查/启信宝/企查查/小红书/知乎/微博/脉脉建立可观测的来源能力矩阵，至少表达：直接公开访问、仅搜索索引、需已有接口凭据、不可达/未实现。不强求全部直连，但不允许冒充已接入。

## 5. 数据和分析规范

以下是建议的内部模型，可适配已有结构，不是要求照抄字段名，也不是直接修改公共 schema 的许可。

### 身份模型

保留 legal name、brand、alias、统一社会信用代码、股票代码及市场、集团/子公司关系、城市和匹配状态。身份不明确时返回多个候选或明确未解决，不自动选择第一条。数字子串不能作为公司身份匹配；股票代码保持标准宽度与市场，包括港股前导零和 A 股 688 等情况。

### 证据模型

至少可表达：

- 稳定 evidence ID；company ID；job ID 或 null；company/group/department/job 等范围。
- channel、platform、provider、access mode（正文/PDF/索引摘要/用户文件）。
- title、canonical URL、发现 URL、原始或归一化内容哈希。
- 采集时间；发表时间；材料覆盖期；经历期，各自允许未知。
- 原文摘录及可定位信息：网页段落、PDF 页码、表格行列和单位。
- 原始材料的存储位置、解析器版本、内容与实体匹配结果。
- 从哪里发现、搜索 query、来源谱系/转载关系、关联维度列表。

原文与 AI 总结分开保存。库中保存足够内容，传给模型的片段有预算；完整证据仍可追溯。重复采集相同材料不重复增加独立来源数。

### 事实、主张和翻译

分别存储 source claim（来源声称）、normalized fact（结构化提取）、assessment（跨证据判断）和 seeker translation（对用户的解释）。事实至少有 evidence IDs、原文位置、主体/岗位/时间/口径/单位、状态和规则版本。重要数字须有可回查的表格位置或原文，不由模型凭记忆生成。

引用必须验证：证据确实存在、属于本次可用快照、主体相容、摘录确实对应。ID 校验通过只说明结构有效，不代表语义支持；另行检查范围、否定、条件和时间。

每条用户解释尽量包含：

1. 看到了什么：引用支持的材料和事实。
2. 对此岗位可能意味着什么：明确标为推断，说明成立条件。
3. 为什么与你相关：对应用户已确认关注点。
4. 还不知道什么：数据与范围限制。
5. 应询问什么：具体、可核实的问题。

不要统一输出武断“好公司/坏公司”评分。若已有推荐规则，保留事实/推断/未知的边界；不得把缺失数据当作零风险。

### 财报和风险提取

首轮优先：收入、净利润、经营现金流、货币资金、总资产、总负债、借款或流动负债、审计意见/重大不确定性、员工数量及其口径、明确披露的重大经营事项。不要为了表格完整而凑数字。

必须识别合并报表 vs 母公司报表、报告期 vs 对比期、人民币元/万元/亿元、正负号和币种。比率仅在口径一致、分母有效时计算，并保存公式与输入。缺某项保留 null。员工数变化不是自动裁员结论，异常数值要求回查原表。

PDF 解析可先用环境现有轻量库建立正文与页码闭环，再在资源允许时评估 Docling 的布局和表格能力；选择由实际解析质量决定。若表格对不齐，不提取该数字，保留原页定位和解析失败。扫描件 OCR 失败必须显式记录。

风险事件至少表达事件类别、主体、日期、来源、事件状态与已知金额。处罚、争议、案件和已生效结果不得混写；同名公司材料不得误归属。

### 跨源核对与置信度

置信度显示高/中/低/未知，可用透明规则生成，不捏造百分比。考虑身份匹配、材料是否完整、可定位性、时效、独立来源和范围一致性。官方材料对“它披露了什么”可以提供较强支持，但不能证明未披露的岗位待遇。

只有主语、时间、岗位范围和口径可比时才判矛盾。旧员工经历和新招聘安排可并存，优先标时间差异；总部和子公司待遇差异先标范围差异。相同事件被十个站转载不算十份独立支持。匿名体验允许产生待核实线索，不升级为已核验普遍事实。

### 来源状态和补查

每次来源尝试区分：ok、empty、blocked/login_required、timeout、parse_error、not_configured、unsupported 等。保留请求阶段、耗时、数量、错误类别，不在日志写密钥或个人资料。

补查先针对“哪些用户重要问题缺证据”生成计划，再选择可能补足的渠道。每次给出 query、目标主体、所需材料类型、原因和预算。首轮默认最多两轮补查，可配置；第二轮没有新增独立有效证据时停。不得全量重复原搜索，也不得把预算耗尽改成支持。

## 6. 分块执行：每块有输入、产物和门槛

建议八小时内按下列顺序推进。时间仅为执行预算，不是工期保证。前四小时优先打通最小闭环；后续用于补渠道、审查、集成和验证。不要在第一阶段花数小时搭新框架。

### 阶段 0：接管与基线

读取仓库的实际 AGENTS.md、README、贡献要求和相关代码。检查工作区改动、远端地址、分支、Node/Python 版本、依赖、Git LFS 和已有测试。保存当前 base SHA。

使用隔离目录保护现有工作。远端已有 `agent-v2` 时先检查它与基线的关系及已有改动，适合则续做；不适合则在隔离目录构造可正常快进或合并的方案。不得强推、覆盖或假设远端分支一定不存在。基线优先 remote 默认分支；若已有同任务版本，记录续做依据。

产物：`docs/agent-v2/BASELINE.md`、`IMPLEMENTATION_PLAN.md`、`PROGRESS.md`，记录基线检查与环境阻碍。已有失败与新失败分开。

门槛：知道生产入口、报告消费者和模型/工具协议；不只根据目录名画图。

### 阶段 1：统一证据、身份与迁移

先实现内部证据/claim/来源状态模型、稳定 ID、幂等写入、身份匹配与范围约束。借鉴或复用 MARA 的适用模块，但按现有 TypeScript/Python 边界适配，不整套搬入其网站。

建立 agent 专用库迁移与旧记录读取适配；旧摘要可读取，但不得假装拥有原文全文或准确日期。新增表首次创建/重复启动可安全执行。保留旧报告读取能力。

门槛：相同材料重跑不增加事实和独立来源数；同名不同主体不混；旧库不写入；现有公共接口仍通过校验。

### 阶段 2：先打通企业披露纵向闭环

实现：公司与市场识别 → 公开披露文件发现 → 有限下载 → PDF/HTML 正文提取 → 原文及页码存储 → 一项经营/资产事实 → 面向求职者解释 → 网站报告中的可点击证据。

可选真实样本：中控技术，股票代码 688777。示例文档链接为 https://static.cninfo.com.cn/finalpage/2026-04-21/1225131222.PDF 。执行时验证文件、主体、报告名称和期间，不依据链接日期猜报告年度。若不可达，选择其他实际公开报告并说明替换。不要把示例的财务数字硬编码为样本真值。

必须保留网页页码/PDF 物理页码与印刷页码的区别。私企无财报路径也要返回明确缺口。

门槛：至少一份真实材料贯通，数字有原表回查；没有网络时离线 fixture 贯通且真实验证标为受阻，不冒充完成真实来源验证。

### 阶段 3：四渠道适配器与覆盖扩展

实现四类工作器和渠道接口，复用已有搜索提供方；修复实际存在的 HTML 解析、伪链接、摘要裁剪和错误区分问题。搜索结果发现与正文获取分开，正文不可得时仅保留摘要级材料。

为企业信用、招聘/采购、社区经历各完成一个可运行入口，输出统一 evidence 和 source attempt 状态。以公开来源能力矩阵展示指定平台现状。网络可用时每类至少验证一个真实公开材料；否则提供可执行入口、离线验证与明确障碍。不得只创建七个空类就宣称渠道接入。

招聘/采购至少有一条福利采购内容的提取 fixture，并明确计划/中标/合同/验收阶段。社区至少验证索引摘要与正文的区分，以及匿名/岗位/经历时间缺失的处理。

门槛：结果进入共享库、同一材料可跨维度使用；失败渠道不会令整个任务丢失已完成证据。

### 阶段 4：分析、反证与补查

实现有范围的 claim 提取、财报口径检查、否定/条件解析、同源去重、矛盾审查、可配置的缺口补查和置信度规则。优先确定性规则处理数字、单位、ID、日期和匹配；模型用于有限的解释或提取，输出需 schema 校验和原文支持检查。

可从 GPT Researcher 提取轻量的研究任务/检索器/反馈机制；有问题的自动接受逻辑不得保留。没有模型密钥时核心提取和证据展示仍可工作，模型解释标为不可用。

门槛：不加班、没有年终奖、奖金有条件等不被误反转；旧/新时期或不同部门不被强行认定矛盾；补查有停止条件。

### 阶段 5：网站、报告和运行恢复

接入现有 B 调查和 C 报告。优先服务端/报告内容改进，保持现有页面风格与用户流程；不要顺便重做 UI。面向用户展示发现、证据、岗位适用范围、未知和核实问题，来源能力细节放在可展开的资料说明。

处理现有工具输出大小、报告上限、缓存和后台任务限制：完整资料留库，模型分片或摘要有引用指针；展示选择与采集覆盖分开，不能因前端四条上限把其余材料丢失。

采集分阶段提交，任务保存检查点。针对被取消、工具超时、进程结束或重启，保留完成材料并可恢复；付费模型调用用请求状态和幂等策略防止自动重复计费。对状态不明的付费请求不得盲目重试。

缓存键包含主体、范围、查询/解析/规则版本和有效期。缓存策略区分确实空结果、解析错误和被拦截，避免把失败缓存成不存在资料。缓存过期展示旧数据时要显示时间，不能当作本次采集。

门槛：本地网页可操作并能生成有引用的报告；开关关闭、无密钥、部分失败、数据缺失时均有清楚降级。

### 阶段 6：验收、交付、推送

完成下一节的验收，修复新增失败。导出合成完整案例和经过核实、适合提交的少量公开摘录案例；大文件、私人报告、完整社交内容和运行日志不要入库。

产物：架构、复用清单、来源能力矩阵、验收结果、运行说明、已知限制和审查包。完成任务范围内的正常提交和 `agent-v2` 推送，核实远端 SHA 与本地一致。

若八小时预算将耗尽，停止低优先扩展，留下一个可运行版本和真实未完成清单。至少预留最后一小时做集成验证、文档和推送。允许推送标为“部分完成”的可运行结果，绝不能把未完成验收写成全部通过。

## 7. 验收：用会暴露误判的案例

测试关注真实行为，不能只检测函数存在、返回非空或调用次数。合成材料全部标 `fixture` / `demo`，不得进入 live 报告。以下回归必需，可合理组合测试：

| 场景 | 必须出现的行为 |
| --- | --- |
| 同名不同公司或集团/子公司 | 身份不明确时不混入证据；公司层材料不冒充岗位承诺 |
| 港股前导零、A 股 688 开头 | 标准化后匹配正确市场和代码，不用任意数字子串匹配 |
| 同文被三个网址转载 | 独立来源数不算三；原来源与转载关系可回查 |
| 一份年报同时含经营与员工信息 | 单条原始材料关联多维度，不重复编造独立证据 |
| 注册资本高但现金未知 | 不推断资金充足或岗位稳定 |
| 利润为负但现金流为正 | 分开解释，不生成工资拖欠结论 |
| 元/万元、合并/母公司、两年列倒置 | 口径正确；不确定则不输出对应数值 |
| 招聘 20–30 万含奖金、固定底薪未知 | 不编出确定固定月薪 |
| “不加班”“没有晋升通道”“暂无年终奖” | 正确识别否定和条件，不凭关键词或情绪生成事实 |
| 旧员工体验与新制度、不同部门体验 | 保留时间/范围差异，不伪造直接矛盾 |
| 食堂采购计划或中标公告 | 只产生相应采购阶段线索，不称员工已享受福利 |
| 登录页、验证码、超时、搜索空结果、解析错误 | 具有不同状态；报告不称“没有风险/没有相关材料” |
| 重跑同公司、取消后恢复 | 幂等、检查点有效，已有证据不丢失 |
| 模型引用不存在 ID 或错误主体材料 | 被拒绝/修复，不能通过正常报告校验 |
| 补查没有增益或用完预算 | 停止并保留未知，不自动通过审查 |
| 来源只有搜索摘要 | 明确摘要级别，不生成原帖全文、评论量或身份信息 |

执行实际仓库支持的已有检查。当前可用命令线索：

```text
npm run typecheck
npm test
npm run test:b
npm run test:c
npm run test:integration
node --import tsx --test modules/research-agent/research.test.ts packages/integration/research-jobs.test.ts
python modules/research-agent/test_worker.py
npm run build
```

Python 使用项目实际虚拟环境解释器；命令可能随仓库变化调整。公共契约或 A 页面受影响时再运行 A 相关测试，不机械扩展无关测试。基线错误单列，不为掩盖失败修改断言。测试记录写执行命令、时间、退出结果和限制。

网络与模型验证分开报告：离线逻辑通过、真实来源是否可达、模型接口是否调用成功、网页是否实际操作过，四者不能互相替代。禁止把 fixture 成功写为真实采集成功。

### 最小对比评估

对相同公司/岗位/用户关注点，在同一时间窗口保存旧版和新版输入与输出，尽量使用相同来源 fixture 确定改造效果。再补真实来源观察，不能把不同时间的网络波动直接归因于算法。

记录：渠道尝试及状态、可定位原始材料数、独立有效来源数、事实可追溯比例、未知/矛盾处理、运行耗时、实际模型用量。若无旧版可运行环境，写明未做旧新实测；不要编造提升百分比或费用。

## 8. 运行质量与工程约束

- 保留现有 TypeScript 网站与 Python 边界，除非有明确、可验证的必要理由。不要新增整套 LangGraph/DeerFlow/第二个网站作为绕路。
- 并发、超时、最大文件大小、每公司请求上限、补查轮数、模型调用预算均可配置，有保守默认值。新增收费服务默认未启用；没有凭据不硬接。
- 正文/PDF 下载只接受受控 HTTP(S) URL；拒绝本地/内网/元数据地址及重定向后的同类地址；工具参数不允许任意路径或命令。避免把下载器变成服务端任意访问入口。
- 错误明确但不泄露环境变量、密钥、完整用户画像。继续保持个人信息与外部企业调查材料的分离边界。
- 模型不得自主执行网页/PDF中的指令；只能调用受控调查工具，不获得任意 shell 权限。
- 不修改原上传数据库；不调用原 vendor 中会注册公司、全库分析或破坏数据的入口来“快速修复”。
- 新功能有开关或明确兼容路径，关闭时原站仍能工作。失败保留已有材料，不能返回假的完整报告。
- 依赖和第三方代码锁版本，写迁移与回退说明；不提交 `.env*` 密钥、缓存、venv、node_modules、下载目录、数据库副本、大型 PDF 或用户信息。
- 工作进度约每个阶段记录一次，长阶段至少每三十分钟保存可恢复检查点。用户休息期间无需等待普通选择；仍向当前聊天简短说明关键进展与阻碍。

## 10. Git 提交和远端核验

1. 检查远端确实为目标仓库，工作分支确实为 `agent-v2`。
2. 按阶段提交本任务文件，避免提交无关用户改动；每个提交说清具体能力和验证。
3. 提交前检查 staged diff、新增大文件、敏感信息和第三方 notices。
4. 推送前获取远端当前状态。有并发改动时先正常协调合并并验证，不强推。
5. 正常推送 `agent-v2`，用远端分支查询核对 final SHA，记录命令真实结果。
6. 推送只保存分支，不代表已部署；如果仓库存在分支部署工作流，应先阅读其触发规则并在交付中记录实际行为。
7. 不要求创建 PR；若确有必要且当前用户授权覆盖该动作，可创建草稿，但不要合并。此次首选直接交付分支链接。
8. 若 GitHub 认证失败或没有写权限，保存本地 commits 和可移交 patch/bundle，写清失败原因与恢复命令。不得声称上传完成，不重复索取用户尚未提供的凭据。

最终回复应包含：远端分支链接、本地与远端核对后的 final SHA、实现了哪些真实能力、实际复用了哪些代码、通过/未通过哪些检查、尚缺哪些来源、如何本地启动、审查包路径。若部分完成就明确说部分完成。

## 11. 完成判定

完整交付需要：四类渠道调度和实际采集入口、统一证据库、企业披露正文与资产/经营信息提取、招聘采购与社区范围信息、可追溯事实与有界解释、缺口补查、现有网站集成、关键测试和真实能力记录、第三方许可记录、`agent-v2` 远端核验。

对不可公开获取的平台，不要求伪造直连；但必须有状态、替代公开路径和已验证能力记录。关键真实来源验证受阻时可以提交可运行代码，但整体完成状态标为部分完成/待真实验证。

以下都不能算完成：只换提示词；只增加 agent 名称；只输出年报标题；只跑 demo；只做静态报告；把缺失显示为低风险；把匿名经历变成岗位承诺；虚构开源复用；把预算耗尽当事实通过；只在本地提交却声称已经推送。

验收优先级：先保证证据真实和范围正确，再保证链路可运行，再扩大来源覆盖，最后优化表达和性能。
